Executive Summary & Commercial Value

CampusFood is a specialized, turnkey meal subscription and delivery platform engineered specifically for university campuses, student housing blocks, and institutional catering operations.

💰 Predictable Cash Flow

Transforms volatile daily meal transactions into upfront 30-day subscriptions. Customers pay before service begins, securing working capital for food inventory.

🍲 Zero Food Waste

Kitchen orders are strictly locked to predefined service windows. Chefs prepare exact batch quantities based on aggregated student orders, eliminating unsold surplus.

🏢 Clustered Batch Delivery

Dispatches meals directly to designated campus dorm buildings (e.g. T22, T34) in consolidated runs rather than individual home deliveries, slashing delivery logistics costs.

Key Commercial Advantage: Zero 30% App Store Taxes

Built as an installable Progressive Web App (PWA). Students install it straight from the browser on iOS and Android with no app store downloads, avoiding Apple/Google's 15%–30% in-app revenue cuts and third-party delivery marketplace commissions.

Operational Walkthrough: The User Journeys

The platform segregates access automatically into two dedicated workflows based on the user's role flag (is_manager) in the database.

A. Student (Customer / Subscriber) Journey

1
Instant Phone Authentication
Students register or sign in with their phone number and password. No complex email confirmations are required.
2
One-Time Campus Onboarding
First-time users enter their Full Name, Student Identity Number, and select their primary dorm pickup point (e.g., Building T22 or T34).
3
Monthly Subscription Pass & Payment Proof
Students transfer the monthly meal fee via bank transfer or mobile banking (e.g., Telebirr / CBE) and input the Transaction Reference Number. The pass is queued for manager verification.
4
Time-Locked Meal Selection
During active meal windows, students select their single preferred meal from the day's menu. An automated database constraint strictly prevents double-ordering:

• Breakfast Window: 07:00 – 08:00
• Lunch Window: 11:00 – 13:00
• Dinner Window: 17:00 – 19:00
5
Real-Time Delivery & Dorm Arrival Alert
The student tracks their meal status: Pending → Packed → Arrived → Delivered. When food reaches their dorm pickup station, an instant pop-up banner alerts them to collect it.

B. Kitchen Manager & Dispatch Operator Journey

👨‍🍳 1. Kitchen View (Preparation Totals)

Aggregates live counts across all student orders for the active meal slot. Chefs see consolidated dish summaries (e.g., "52 Enjera with Shiro, 38 Pasta Bolognese") with zero manual tallying.

📦 2. Packing & Dispatch Workspace

Orders are grouped by dorm building (T22 Female Dorm / T34 Male Dorm). Includes packing checklists, "Mark All Packed", and "Dispatch to Building" triggers that alert all waiting students.

📋 3. Menu Management Suite

Full control to add, edit, or delete items offered for Breakfast, Lunch, and Dinner. Changes reflect instantly on student dashboards without needing code deployments.

💳 4. Subscription Verification Queue

Reviews pending student payment transaction codes. Managers click Approve (which automatically extends access by 30 days) or Reject with preset error feedback.

Database Integrity & Security Policies

The platform enforces business rules at the database level inside PostgreSQL, meaning malicious users cannot bypass client-side rules via automated API scripts:

🛡️ Row Level Security (RLS)

Every table (users, menu, orders) has strict RLS enabled. Students can only select and mutate their own data. Only managers can update order statuses or manipulate menu offerings.

⏱️ Stored Function can_submit_order

A PostgreSQL stored function runs on order insert. It verifies that: (1) The user's subscription is active, (2) the current server time in Africa/Addis_Ababa is within the meal's open window, and (3) meal type matches.

🔒 Duplicate Order Prevention

The database schema enforces a unique constraint orders_one_per_user_per_meal_per_day on (user_id, meal_type, order_date), making double-ordering physically impossible.

⚡ Automated Timestamps

Trigger functions (set_updated_at) automatically timestamp all order status modifications and user profile updates for audit accountability.
